# 공개 자료 학습·성능 개선·장비 없는 검증

이번 작업은 공개 데이터로 모델을 추가 학습하고 기존 모델과 비교하며, CPU/GPU 추론 경로와 장비 없는 전체 업무 흐름을 검증한 결과다. 모든 작업 파일·캐시·별도 Python 환경은 프로젝트 안에 두었다. 원자료와 가중치는 로컬에만 보관하고 코드·집계·재현 절차만 Git으로 관리한다. 사용자 ZED 녹화는 이번 학습·평가에 사용하지 않았다.

## 정확도

| 평가 항목 | 기존 | 추가 학습 | 평가 범위 |
|---|---:|---:|---|
| 포트홀 AP50 | 18.04% | 60.03% | 고정 MWPD 양성 97장 + 새 RDD 일반 노면 48장 |
| 일반 노면 오탐 박스 | 12 | 8 | 위 일반 노면 48장, confidence 0.1 |
| 도막 IoU | 49.28% | 56.98% | 새 recording 2개에서 고정 80장 |
| 도막 IoU 회귀 | 48.75% | 56.38% | 과거에 확인한 TEST 100장, 독립 평가 아님 |
| 얼굴 재현율 | 94.30% | 93.68% | 새 얼굴 100장·GT 649개, confidence 0.01 |
| 번호판 재현율 | 98.00% | 98.00% | 새 번호판 100장·GT 100개, confidence 0.01 |

포트홀은 고정 12 epoch·실제 optimizer update 3,261회 중 VAL 기준 epoch 7을 선택했다. 기존 도메인 VAL AP50이 68.39%에서 65.68%로 2.72%p 하락한 비용도 있다. 차선은 사전 조기 종료 조건으로 12 epoch·2,388 update를 수행하고 epoch 6을 선택했다. 모델·임계값을 VAL에서 고정하고 원시 출력과 후처리 정합성을 확인한 뒤 최종 평가를 수행했다. 최종 평가 결과로 재선택하지 않았다.

비식별화는 번호판 파라미터를 고정하고 얼굴만 추가 학습했다. 새 코호트에서 얼굴 AP50도 88.10%에서 87.62%로 소폭 하락해 개선을 확인하지 못했다. 후보로 운영 모델을 교체하지 않고 기존 비식별화 모델 유지를 권고한다. 이 결과를 본 뒤 추가 학습이나 TEST 기반 임계값 조정을 하지 않았다. 알려진 클래스에 대한 조건부 평가이므로 번호판 자료 안의 얼굴 등 라벨 없는 다른 클래스 누락까지 검증한 것은 아니다.

포트홀 AP50 80%, 도막 IoU 75%, 비식별화 최소 클래스 재현율 95% 목표에는 미달한다. 해외 공개 자료의 작은 고정 코호트이며 국내 실제 도로·ZED 보정·마모율 MAE·도로별 오탐/km의 검증을 대신하지 않는다. 도로·촬영일·인물의 물리적 독립성도 확인하지 못했다. [포트홀 학습·출처·수치](POTHOLE-MWPD-TRAINING.md), [차선·비식별화 계획과 결과](PUBLIC-REFINEMENT.md)를 참고한다.

## 실행 성능과 재현 범위

기본 CPU2thread 직렬 동작을 유지하고 명시적 CPU fast 옵션과 별도 프로젝트 환경의 CUDA shared-memory worker를 추가했다. worker의 종료·timeout·잘못된 tensor·CPU-only fallback을 실패로 처리하며, 검증한 모델·가중치·실행 환경·소스에 결합한 profile만 사용한다. GPU 가속이 있다는 이유만으로 새 모델을 지원 상태로 간주하지 않는다.

이전 세 모델과 변경 전 소스 `afb734a`에서는 공개 VAL 160건의 CPU/GPU 원시 출력·후처리 검사가 모두 통과했다. 합성 warmed 2D pipeline의 CPU median 1.044FPS와 CUDA median 6.015FPS를 관측했으며 10FPS 목표에는 미달했다. load·warmup·teardown과 capture/decode/GNSS/API는 이 warmed 수치에서 제외했다. 이 과거 수치를 새 가중치나 후속 변경에 소급하지 않는다.

추가 전처리 복사 축소는 계산 순서·크기·정규화·threshold를 유지했다. 두 NumPy/OpenCV 환경에서 각각 828건과 적용된 실제 전처리 828건의 비트 단위 동일성을 확인했다. 합성 마이크로벤치에서 1920 검출 입력은 약 18~19ms, 차선 입력은 약 12ms 절약했다. 이를 더해서 전체 FPS로 환산하지 않는다. [실행 성능 범위](INFERENCE-PERFORMANCE.md), [복사 비용 측정](PREPROCESSING-MICROBENCH.md), [새 모델 GPU 검증 절차](GPU-MODEL-SET-VALIDATION.md)를 참고한다.

새 연구 후보 세 모델도 사전에 고정한 공개 VAL 160건을 직접 GPU 진단과 실제 앱 공유메모리 경로에서 각각 검사해 원래 raw/post 기준을 모두 통과했다. 모델·평가 worker와 전체 pytest가 종료된 뒤 같은 후보 조합을 ABBA 순서로 한 번 측정했다. warmed 합성 2D pipeline은 CPU default median **1.133FPS → CUDA fast 7.793FPS**였고 마스킹 PNG 바이트도 같았다. 추론·전처리·후처리·품질·추적·마스킹·PNG/JSON을 포함하며 load·warmup·teardown·capture/decode/GNSS/API는 이 warmed 수치에서 제외한다. 10FPS 목표에는 미달한다. 이전 6.015FPS와는 가중치와 소스가 달라 그 차이를 복사 최적화 단독 효과로 해석하지 않는다. 비식별화 후보의 정확도 퇴보에도 불구하고 검증 중 조합을 바꾸지 않았으며, 이 실행 호환성 검사는 운영 승격을 뜻하지 않는다. [새 모델 수치·실행·속도 증거](FINAL-MODEL-GPU-VALIDATION.md)에 상세 조건을 기록한다.

## 장비 없는 전체 흐름

실제 ONNX Runtime과 비개인 합성 영상으로 분석→추적→마스킹→암호화 로컬 큐→검수→전송→관측·사진→브라우저→CSV→개인정보 삭제까지 확인했다. 503 주입 후 큐 재개, stale version 409, 검수 없는 전송 거부, 삭제 후 410와 재업로드 차단도 포함했다. 이 결정적 ONNX fixture는 학습된 AI의 정확도 증거가 아니다.

별도 기존 실제 연구 모델의 CPU 연속 추론은 600.78초·633프레임·오류 0으로 완료했다. 후속 보관정책·전처리 변경이나 새 가중치의 10분 검증으로 확대하지 않는다. 메모리 작업 집합의 처음과 끝 차이는 73,728바이트였으나 메모리 누수가 없다는 일반 증명은 아니다. [전체 업무 흐름](HARDWARE-FREE-WORKFLOW-VERIFICATION.md), [연속 실행](INFERENCE-SOAK.md)을 참고한다.

검사 중 미검토 분석 사진의 기한과 서버 업로드 후 기한 상속 문제를 발견해 수정했다. 미검토 기본 7일, 승인한 별도 사본 기본 90일에 더 이른 원자료 기한을 적용한다. 실제 15초 기한 경과 후 사진·관측·캐시 보고서 접근 차단도 HTTP로 확인했다. [기한 상속 구현](LOCAL-MATERIAL-RETENTION.md)을 참고한다.

모든 writer 종료 후 공개 자료와 파생 파일의 정확한 17개 범위에서 6,509개를 별도 보관 목록에 등록했다. 기존 inventory·계획 6개의 고정 SHA는 유지했고, 등록 시점의 dry-run은 모두 기한 전이었다. 실제 파일 삭제·기한 연장·자동 스케줄 설정은 0이며 사용자 녹화는 제외했다. 개별 경로·이미지 SHA를 제외한 [보관 집계](reports/PUBLIC-CYCLE-RETENTION.json)와 [절차·완료 기록](PUBLIC-CYCLE-RETENTION-PREPARATION.md)을 참고한다.

## 소프트웨어 검사

마지막 변경을 포함한 전체 Python 재검사 702건과 하위 검사 189건이 통과했고 실제 HTTP 75건을 포함한다. 별도 GPU opt-in과 Windows symlink 권한 검사는 기본 실행에서 이유를 표시해 건너뛰었다. 이어 등록한 새 후보 profile로 실제 GPU opt-in 1건을 따로 통과했다. TypeScript/Vite 빌드와 브라우저 25개 시나리오가 통과했다. 브라우저 및 최종 Python 검사 각각의 서버 로그 8개에서 새 오류·traceback은 0이다. 상세 실행 범위와 로그 집계 SHA는 [검사 결과](reports/PUBLIC-CYCLE-SOFTWARE-VERIFICATION.json)에 보존한다.

실물 ZED 연결·GNSS·카메라 보정·거리/깊이 정확도·실제 주행 지속 처리율·현장 개인정보 검수는 여전히 별도 확인이 필요하다. 기본 운영 모델을 자동으로 교체하거나 현장 합격 상태를 부여하지 않았다.
