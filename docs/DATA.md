# 4. 수집·입고·처리 흐름

1. A가 촬영 목적·장소·범위·운영 근거·표시/문의처·수집 담당을 기록한다. C가 차량 고정·시야·렌즈·저장·GNSS·프로파일을 확인한다.
2. 촬영은 run UUID로 묶고 좌우 영상·프레임 시각 매핑·원시 GNSS·취득 manifest를 암호화 로컬에 저장한다.
3. 입고 시 파일 해시·영상 디코딩·좌우/시각·누락·오염·프로파일 일치를 검사한다. 이상 자료는 사유와 함께 격리한다.
4. 원본 보관 기한 내에 얼굴·번호판을 가리고, 외부 공유 메타데이터의 상세 위치·EXIF·음성 등 불필요한 항목을 제거한다. 마스킹 전 학습/평가가 필요한 범위는 원본 접근 기록과 7일 정책 안에서만 처리한다.
5. 마스킹 라벨 원본과 편집/내보내기 결과를 버전 관리한다. 분할·검수 통과 자료만 release에 포함한다.
6. 모델 학습은 특정 dataset release·split manifest·가중치·코드/환경 해시를 연결한다. 서버에는 사람 검수와 해시 승인까지 끝난 사진·관측 결과만 전송한다.

파이프라인 단계는 acquired→quarantined 또는 redacted→labeled→qc\_passed→split\_locked→released→expired/deleted로 기록한다. rejected/held 자료는 정상 음성으로 자동 변환하지 않는다. 영상·라벨이 보관기한을 넘기면 출시 목록에서도 차단하고 삭제/대체 이력을 남긴다.

# 6. 데이터 분할과 누수 방지

## 6.1 분할 단위

프레임 무작위 분할을 금지한다. 동일 실물 포트홀·차선 구간, 겹치는 노선, 반복 주행, 좌우 영상, 크롭/증강/재인코딩, 동일/유사 공개 이미지가 연결되면 하나의 leakage\_group\_id로 묶는다. 위치가 있는 자료는 노선·촬영 영상·영상 외관을 함께 확인한다. GNSS 10 m 근접만으로 같은 장소인지 단정하지 않는다.

공개 파일의 촬영 순서/장소가 없으면 제공 원시 ID·연속 파일 prefix·해시·유사 영상으로 묶고, 독립성을 증명하지 못한 자료는 자체 시험셋에 섞지 않는다. 공급자의 공식 test 구분을 임의로 학습에 합치지 않는다.

## 6.2 비율·수량 우선순위

학습/검증/시험은 연결 그룹 기준 약 70/15/15를 목표로 한다. 실물·노선 분리와 독립 시험 표본 수를 비율보다 우선한다. 공개 데이터의 공급자 분할·목적 제한은 별도로 존중하고, 자체 최종 시험은 자체 수집의 독립 장소/노선으로 구성한다. 자료 종류별 그룹 수·프레임 수·실물 수·구간 수를 따로 공개한다.

양호/관찰/마모 후보 각≥20개는 시험 표본 구성 목표다. 학습 클래스 과표집·증강은 train에만 적용하며 test의 실제 분포를 바꿔 성능을 높이지 않는다. 클래스 균형 시험과 실제 연속 5 km 시험은 서로 다른 평가이며 둘 다 보고한다.

## 6.3 잠금·변경

W6 말 A가 split manifest·seed·그룹 연결 근거·라벨 버전·해시를 잠그고 test 쓰기 권한을 회수한다. 검증셋으로 임계값을 정하고 W7에 시험한다. 시험 장면을 보고 모델/임계값을 고쳤다면 새 버전·별도 시험셋으로 재평가한다. 라벨의 사실 오류 수정은 모델 결과와 독립 검토하고 이전/수정 지표·사유를 함께 남긴다.

누수가 확인되면 연결 그룹 전체를 재배정하고 파생 자료·학습 lineage를 추적한다. 영향 모델/시험 성적은 유효로 유지하지 않고 재학습/재평가 대상에 표시한다.

라벨 쌍의 초기 QC 목표는 클래스 일치율≥95%, 포트홀 bbox IoU≥0.80, 도막 IoU≥0.85, 외곽 IoU≥0.90, 잔존율 차이≤5%p다. 이는 <b>작업자 간 라벨 품질 목표</b>이며 SRS 모델 성능 목표와 다르다. 시험 GT의 미합의는 수치가 높아도 판정 보류한다.

중대 오류(개인정보 누락·분할 누수·양성 누락/오분류·잘못된 좌표계) 1건이면 배치를 반려하고 원인 유형 전수 재검수한다. 일반 경계 오류는 정정 후 재표본 검수하며 표본 지표 미달 시 배치 전체를 재검수한다. 시험의 confirmed 양성을 held로 바꿔 Recall 분모에서 빼지 않는다.

# 8. 개인정보·권한·공유 기준

촬영 목적·근거·대상·표시·문의처와 학습 이용 목적을 수집 계획에 기록한다. 촬영 표시만으로 모든 촬영/재사용이 허용된다고 해석하지 않는다. 이동형 기기의 개인영상 처리 원칙은 개인정보위 안내서를 참고한다. [개인정보위 공식 안내서](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS217&mCode=D010030000&nttId=10679)

학습에 불필요한 얼굴·번호판·음성·세부 이동 경로는 최소화한다. 개인정보 검출 모델용 표본은 동의받은 연출 자료 등 목적과 조건이 확인된 자료를 우선 사용한다. 마스킹했더라도 위치·시각·차량 외관과 결합해 식별될 수 있으므로 자동으로 익명정보라고 간주하지 않는다.

외부 공유는 reviewer/admin이 최종 파일을 확인한 뒤 SHA-256에 연결해 승인한다. 승인 뒤 파일을 수정하면 재승인이 필요하다. 서버는 기기 토큰·승인자·기관·최종 해시를 검사한다. 라벨 JSON·썸네일·PDF·시연 화면도 공유 검수 대상이다. 공용 Notion에는 실제 원본·얼굴/번호판 표본·상세 주행 궤적을 첨부하지 않고 승인된 설명/집계만 올린다.

삭제 목록을 반영할 수 없는 통짜 상세 자료 백업은 만들지 않는다. 기본은 스키마·설정·복구 절차 중심이며, 상세 백업을 추가할 때는 개별 TTL·삭제 요청이 사본에도 전파되어야 한다. 복원 서비스는 삭제/만료 필터 적용 후에만 공개한다.

# 10. 버전·재현·재배포

release ID는 data-v1.0.0처럼 관리한다. 클래스/마스크 의미·좌표계 변경은 major, 새 자료·라벨 합의 추가는 minor, 오탈자/비의미 메타데이터 정정은 patch로 올린다. 버전명 외에 실제 manifest·파일 해시를 기준으로 재현한다.

release note에는 출처·조건, 날짜/촬영 조건 분포, 클래스·실물·구간 수, 제외/불가 사유, split 그룹/해시, QC 결과, 마스킹 검수, 만료·삭제 정책, 알려진 한계를 적는다. 모델 번들은 dataset release·split·라벨 가이드·코드/환경 해시를 연결한다.

외부 재배포는 자료별 조건과 목적을 확인한 것만 허용한다. 공개 데이터가 섞인 전체 묶음에 임의의 단일 라이선스를 붙이지 않는다. 내보내기본에 원본 URL 인증정보·실제 계정·개인식별 메타데이터를 포함하지 않는다. 만료 뒤 재현이 불가능해지는 부분은 해시·익명 집계·설정으로 남기고 영상이 보존돼 있다고 표현하지 않는다.

# 11. 일정·완료 조건
