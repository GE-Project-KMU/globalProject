# 사용자 주행 기록 수령 및 무결성 확인

사용자가 제공한 `.svo2` 기록 **16개, 총 1,778,740,737바이트**를 읽기 전용으로 조사했다. 모든 파일의 SHA256을 계산했고 서로 동일한 바이트 내용은 없었다. 이 수치는 파일 인계와 바이트 무결성 확인 결과이며, 영상 품질이나 모델 성능 검증 결과가 아니다. 공개 기계 판독 집계는 [RECORDED-DRIVE-INTAKE.json](reports/RECORDED-DRIVE-INTAKE.json)이다.

이 인계 단계에서는 ZED SDK를 실행하지 않았고 컨테이너·재생·프레임 수를 검증하지 않았다. 이후 수행한 [메타데이터 감사](RECORDED-MCAP-METADATA-AUDIT.md)와 [실험적 2D 판독](RECORDED-MCAP.md)은 별도 검증 단계다. SDK를 통한 실제 재생은 여전히 미검증이다. 별도 제공 GNSS 로그와 외부 캘리브레이션 자료는 없다. 유효한 위치·깊이·거리·마모율·모델 정확도를 확보했다고 주장할 수 없다.

원본의 촬영 시각과 원래 보관 만료일은 **미상**이다. 파일 이름이나 수정 시각, 자료 수령일로 촬영일 또는 새로운 보관 기한을 정하지 않는다. 도구는 원본을 이동·수정·삭제하지 않고, 자동 보관·삭제 대상에 등록하지 않는다. 원래 기한과 권리·개인정보 처리 조건이 확인되기 전에는 공개·모델 학습·공유 승인 자료로 취급하지 않는다. 파일 시스템 접근 자체에 따른 운영체제의 접근 시각 갱신 가능성은 별개다.

이후 사용자는 내장 기록 시계가 가리키는 10월 28일이 촬영일로 아마 맞는다고 답했다. 이 추정은 검증된 UTC를 뜻하지 않는다. 11월 4일 보관 기간 확인을 요청한 동안 추가 원본 디코딩·추론을 중지했다. 이후 사용자가 **이번 검증에 한해 2026년 11월 5일 23:59(KST)까지 처리·보관**을 명시적으로 허용하여 검증을 재개한다. 이 예외는 촬영일·기본 7일 정책 변경이나 자동 삭제·자동 보관 등록, 외부 업로드·학습 승인을 뜻하지 않는다. 개별 승인 기록은 프로젝트 내부 비공개 receipt에 보존한다.

## 재현 가능한 인계 명령

프로젝트 루트에서 다음 명령을 실행한다. 입력 경로는 프로젝트 내부에 있어야 한다. 경로의 상위 이동(`..`), symlink, junction과 재분석 지점은 거부한다. 계정이 읽을 수 없는 파일이나 조사 도중 변경·추가·삭제된 입력은 성공 처리하지 않는다.

```powershell
.\.venv\Scripts\python.exe scripts/recorded_drive_intake.py --source "<프로젝트 내부 기록 폴더>"
```

출력은 `data/recorded-drive-intake/<새 인계 UUID>/`의 `private-manifest.json`과 `aggregate.json`이다. `private-manifest.json`에는 파일별 프로젝트 상대 경로·이름·크기·SHA256·보조 수정 시각이 들어 있으므로 공개하지 않는다. 카메라 일련번호를 파일 이름에서 파싱하거나 확인된 장비 신원으로 사용하지 않는다. `.gitignore`의 `*.svo2`와 `data/` 규칙으로 원본 및 개별 인계 메타데이터를 Git에서 제외한다.

공개 집계를 새 파일에 남겨야 한다면 `--public-report docs/reports/<새 집계 파일>.json`을 사용한다. 기존 공개 집계 파일은 덮어쓰지 않는다. 공개 집계에는 개별 파일 경로·이름·해시·수정 시각·장비 식별자를 포함하지 않는다. 재실행 시 새 인계 폴더를 만들며 이전 증거를 변경하지 않는다.

파일을 열기 전후와 전체 조사 마지막에 파일 식별·크기·수정 시각을 비교하고 스트리밍 SHA256을 계산한다. Windows의 `lstat`/`fstat` 간 `ctime` 의미 차이는 변경으로 오판하지 않도록 같은 API의 전후 값끼리 비교한다. 이는 조사 시점의 안정성을 확인하는 절차이며 완료 후 원본이 영구적으로 바뀌지 않는다는 보장은 아니다.

## 검증 범위

합성 파일 검사: 경로 이탈·상위 이동·junction 차단, 재귀 정렬, 바이트 중복, 해시 계산 중 변경 및 계산 후 변경, 파일 추가, 공개 메타데이터 분리, 원본 내용·수정 시각 유지, 기존 출력 보호, Windows 시각 API 차이와 동일 API 변경 검출을 확인했다. 실제 symlink 생성은 계정 권한 부족으로 해당 실행 검사를 건너뛰었으며 junction 감지 분기는 별도로 검증했다. 실제 영상 재생과 개인정보 검수는 이 테스트로 대체하지 않는다.

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_recorded_drive_intake.py -q --basetemp .cache/pytest-drive-intake
```
